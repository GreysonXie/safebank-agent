# 真人转账追问修复

原试用已提供日常账户和金额，Java因张三同名返回RECIPIENT_CLARIFICATION_REQUIRED；模型重复索要付款账户、未给可区分选项。只读记录已定位，禁止为定位再发送付费请求。

1. Java只在当前用户检索结果不唯一时提供有界候选name/note/label以及sourceResolved和是否截断；不提供ID、手机号、金额，不替用户选择。零匹配与多匹配分开。
2. 将候选通过现有resolve_recipient事实目录提供，仍由Java最终引用核验；没有pendingAction不得称已生成预览。
3. 模型输入明确已解析账户及候选区别信息。重复追问已解析账户、遗漏已提供候选区别信息时，用既有预算最多一次重写，失败仍不交付。不将手写数字、用户姓名当银行核验事实。
4. 先观察失败，再修复；免费单元/隔离MySQL/捕获脚本验证，一次独立审查。更新保持DeepSeek试用模式，不主动发模型请求；旧对话/授权/预算保持。
5. 同步开发记录与GitHub；新真实模型表达效果待用户再试，不冒称已经真实生成通过。
