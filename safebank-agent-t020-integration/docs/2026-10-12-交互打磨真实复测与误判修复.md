## 根因与修正

首轮捕获的“已按您的指定生成转账预览”“已为您生成撤销…的待核对操作卡”，在真实对应预览存在时被误判为执行声明。增加有当前预览证据约束的准备措辞支持后，47 项 Java 检查通过，批次 23 两条捕获回答免费通过真实 Java 核验器。

第二轮转账已实际生成 600 元预览，但“已按您的要求把转账金额调整为…”被同一执行声明规则误拒绝。先以原始措辞新增失败回归，再仅允许对应当前转账预览和精确 `preview_transfer.amount_minor` 引用的金额调整说明；其他金额、虚构预览及后续执行成功声明仍拒绝。修正后 49 项 Java 检查通过，捕获原回答通过真实 Java 免费回放。

第二轮撤销不是误判：工具记录只有 `mandate_receipt`，没有 `revoke_preview`，模型却声称已生成操作卡。保留拒绝规则并新增查询清单不能证明生成预览的回归。规划提示明确“先看预览、不要直接执行”仍是准备意图；需要读取时先查询再准备。回答提示明确没有对应预览事实不能宣称已生成卡片。这一提示词修正尚未完成新一批真实语义验收，不能宣称撤销问题已修复。免费回放确认这条虚构预览仍被拒绝。

Python 相关检查 28 项通过。未改数据库结构、授权确认界面或交易提交权限。最新源码与批次 24 测试版本不同，保留原源码摘要，最新版本免费验证另记。
