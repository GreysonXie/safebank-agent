# SafeBank 架构方向与 MySQL 选型记录

2026-10-10。用户明确选择：“用mysql”。本文件记录后续设计方向，不代表数据库迁移或 Python Agent 已实施。

## 当前方向

- Java 21 / Spring Boot / MyBatis 保留，负责可信身份、业务查询、精确金额计算、权限、授权、交易执行、幂等与最终回执。
- 按本轮讨论，后续 Agent 设计采用 Python / 官方 LangGraph，负责理解、规划、对话、澄清、受控工具调用、任务暂停恢复和实际模型发送预算。
- 数据库确定使用 MySQL，业务表采用 InnoDB。精确版本在检查本机环境及检查点适配兼容性后固定；不使用浮动 latest。
- 现有网页保持左侧导航、中间业务内容、右侧对话，移动端对话置于下方。

## 存储职责

初期使用一个 MySQL 实例，业务数据与 Agent 数据使用独立 database 和数据库账号。Java 通过 MyBatis 管理银行业务表；Python 管理自己的 LangGraph 检查点及运行状态。Python 不直接读写银行账户、授权或账务表，通过 Java 受控接口查询和生成操作预览。

两端通过 user/conversation/turn/plan version/action ID 等关联；实际字段、表、索引与接口应在后续设计中明确。Agent 图状态不能替代银行交易状态；共用 MySQL 实例也不自动保证跨服务原子事务。重复恢复必须读取原 action 与回执，UNKNOWN 只核验原动作。

## 后续设计与有限验证

1. 盘点现有业务、风险及上下文表，先设计 MySQL DDL、索引、约束和版本化迁移，再建立或修改代码；不只将 H2 连接地址改成 MySQL。
2. 核查并固定社区 `langgraph-checkpoint-mysql` 与所选官方 LangGraph 的兼容版本。使用本地模拟节点验证保存、暂停、进程重启、恢复及重复恢复，不调用 DeepSeek。
3. 检查点适配不通过时，报告具体兼容问题并处理，不能擅自换回 PostgreSQL，也不使用内存检查点冒充持久化验收。
4. H2 暂保留现有合成测试用途；候选业务迁移另行实施，现行服务和数据保持当前状态。
5. Java 银行业务迁移与 Python 编排各有明确状态所有者；既有四表上下文逐项确定保留、迁移或替代，避免新旧记忆互相覆盖。

MySQL InnoDB 的事务与锁能力见 [MySQL 官方说明](https://dev.mysql.com/doc/refman/8.4/en/innodb-introduction.html)。LangGraph 检查点契约见 [官方文档](https://docs.langchain.com/oss/python/langgraph/checkpointers#checkpointer-libraries)，MySQL 社区实现见 [项目说明](https://pypi.org/project/langgraph-checkpoint-mysql/)。存在实现不等于已经在本项目验证兼容。

此前架构调研中的 Java-only / LangGraph4j 首选及 PostgreSQL 建议保留为历史比较；后续设计以本次 MySQL 选择和 Python LangGraph 讨论方向为准。用户选择数据库不等于已审阅尚未编写的 DDL 与迁移计划。

本轮仅更新选型文档，未安装依赖、创建数据库、改动业务代码、重启服务或调用 DeepSeek。
