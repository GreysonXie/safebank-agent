# v0.4 业务对话修正

用户已确认：在业务范围内，回答需由模型围绕客户具体问题、上下文和业务数据灵活组织；不应按工具名称输出固定模板。

原有AgentService丢弃模型最终回答。修正后接收普通文字或answer_customer输出，模型自由组织解释、追问和建议。可以直接写正常数值或用事实引用填入；程序分别核对金额、比例、日期、币种及引用来源，拒绝缺少事实的数值和无凭证的执行声明。计算工具仅对已取得的数字事实做同类型加减、平均、比例，以及保留首项单位的标量乘除；无银行写权限。季度金额除以季度月份数得到月均折算，不能解释为每月实际扣费。原业务工具、逐动作授权和回执契约不变。

银行事实目录使用稳定的月份标识，避免追问时编号变动；程序补充类别均值、大额合计及占比、明确MONTHLY合计和日历常量。预算目标和建议减少比例允许作为显式假设，但必须在数值所在分句披露，不能冒充银行实际金额。假设参与计算时，产物保留该来源标记，后续引用仍须披露。

会话保留最近完整对话轮次及有限查询证据；追问可以引用已有账单，余额及操作状态须重新查询。同一HttpSession更换用户时清除旧上下文。确认卡、操作状态和写操作暂停继续由程序处理。模型回答校验失败时允许在工具循环内修正；无法修正时显式标注降级，不把模板响应计为正常模型对话。

真实人工复核发现，数字匹配不能阻止错误归因或偏题，因此增加BusinessAnswerReview：同一供应商模型用独立只读请求检查候选含义，审核拒绝则将具体反馈交回主循环修正。审核请求仅接受review_business_answer，既不能调用银行工具，也不能授权任何动作。它检查未知周期混入月付、无渠道证据猜支付方式、比较方向双负号、使用频率及当前问题的限制；同模型审核可能漏检或误拒，仍需人工留出集。

会话已查过授权时，程序在后续轮次刷新当前用户的授权状态给事实目录；原始刷新证据通过contextResults返回，不替换页面已有账单面板。用户切换清除刷新标记。季度/年付月均提供budget_monthly_equivalent，明确为预算折算，不是实际每月扣款。类别最大/最小由程序计算，保留并列，避免用宽泛主语正则限制自然语言。

事实引用和数字约束不等于语义完全正确：把正确金额归到错误交易、错误归因、超出查询范围的推断、建议不恰当仍需多轮评测和人工检查。现有REVOKED代扣只能结合当前查询中的对应对象解释，不能据此宣称另一个ACTIVE对象已撤销。模型解释不是银行回执；商户名称和备注仅为不可信数据，不能借名称伪装执行成功。

实施顺序：先用失败测试复现模型回答被覆盖和追问无差异；实现事实目录、受控计算与回答校验；接入会话和工具循环；保留既有安全回归；真实DeepSeek多轮对话与浏览器验证；独立审查、修正、更新在线入口和验收记录。

验收以真实业务内容为主：同份账单下摘要/大额核对/建议的回答有不同重点；不带月份的追问承接前文；澄清不编造事实；月份比较数值可复算；数字伪造、间接注入和伪造操作成功不能成为权威结论。
