# 回答输入隔离与展示质量改进

2026-10-11，基线6aa4164。沿用Java/MyBatis/MySQL与Python LangGraph架构，界面结构不变。此阶段集中改善真实复验中的枚举外露、重复名称、无关查询时间与授权快照的过度推断。

## 实现

新增answer_catalog作为草稿和重写共用的输入视图：先在原始聚焦目录上计算有效月付分类，再屏蔽status/billing_interval/contract_status的英文引用入口。周期按固定映射提供中文billingDescription，未知或未识别周期保持未确认，不改变金额、对象及总额。原银行回执、原事实目录和Java核验仍完整，未修改银行事实显示或数据库数据。

模型收到的代扣source保留工具来源名，省略包含时间和枚举的冗余注释；未问快照时间/有效期时不传查询观察字段。完整来源与时间继续保存于原回执，既有查询权限与有效期验证不受影响。其他银行工具事实保持现有路径。

提示明确：周期只代表约定，不能推断已经或将自动扣款；引用直接替换完整内容，不在商户/状态引用前重复文字；单项问题不附无关时间。离线确认“是否已实际扣款”会被现有Java执行断言保护拒绝，本轮仅调整提示与固定恢复反馈为“实际交易请以对应账单核对”，没有进一步放宽Java规则。

真实验证原文、usage、回执状态和费用核对见[evidence目录](evidence/2026-10-11-answer-presentation-live/inspection.json)。第一批三题：单项周期/撤销回答已聚焦，无英文枚举、其他服务和查询时间；有效月付金额与名单正确，但名称和状态重复；比较题两稿被“是否已实际扣款”误判拒绝。第二批针对后两题复验，具体结果以阶段最终核对为准。

这是一项输入与表达改进，不是确定性业务语义证明。中文计数、无关排除说明、冗长程度及未来合同状态仍有风险。当前银行工具不确认商户合同状态；将来增加可信合同状态时需提供对应中文展示字段，不能只过滤后静默丢弃。R03/R10保持开放。
