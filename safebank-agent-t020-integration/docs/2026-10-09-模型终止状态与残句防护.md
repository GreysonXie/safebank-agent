# 模型终止状态与残句防护

本轮仅做本地修复与验证，不调用 DeepSeek。上次真实两轮测试的累计用量仍为 10 次请求、91,044 Token，首轮末句残缺，人工完整验收未通过。

## 已确认的问题与改动

旧客户端读取 message 和 usage 后丢弃 choices[0].finish_reason，无法判断供应商是否正常结束。历史记录没有该字段，不能倒推出上次残句的原因；该次回答 completion_tokens 为 51，也不能仅凭残句认定 max_tokens=2048 不足。

按 [DeepSeek 官方响应契约](https://api-docs.deepseek.com/api/create-chat-completion/) 保存固定枚举：STOP、TOOL_CALLS、LENGTH、CONTENT_FILTER、INSUFFICIENT_SYSTEM_RESOURCE、ABORTED、UNKNOWN。缺失、类型错误或其他值均归为 UNKNOWN，原始字符串不进入日志和前端诊断。

- 生成响应仅在 STOP / TOOL_CALLS 时继续处理。其余状态记录 MODEL_RESPONSE_INCOMPLETE，并在解析、分发任何银行工具之前停止，使用已核验数据回退，不自动追加模型请求。
- 审核响应若未完整结束，即使包含看似有效的 approved=true，也按 ANSWER_REVIEW_CONTRACT_INVALID 停止；不能通过，也不能当作有效业务错误继续花额度修正。
- 每次已返回的请求保存 finish_reason、response_complete 及供应商 Token 用量。success=true 表示客户端收到有效消息，并不表示回答完整或业务审核通过。
- question_focus 增加明显残句检查要求，允许正常短句、列表和没有句末标点，不要求固定模板或长度。有效且具体的审核拒绝仍可在原有预算内修正。

## 验证与边界

本地 HTTP 模拟验证终止状态和用量保留；对话模拟覆盖未完成正文、answer_customer、账单查询、资金预览，不允许分发未完成工具调用、不保存部分候选作为客户答复、不产生资金动作。另覆盖未完成审核拒绝及正常终止但语义审核发现残句后的修正流程。

供应商报告 STOP 并不保证语义完整。残句审核提示的真实识别率尚未付费复测，本地脚本只能证明收到有效拒绝后能够修正，不能证明真实模型一定拒绝上次那句残文。也未调整 max_tokens、数据库结构、资金权限或已确认的页面布局。

最终验证：`./run.ps1 package` 构建成功，193 项 Java 测试中 192 通过、0 失败、0 错误、1 项付费联调跳过；Python 评测器 5 项通过。首次全套运行发现旧正常 HTTP fixture 缺少 finish_reason，已补齐正常 stop/tool_calls 状态，并增加 length 响应不能创建资金预览的 HTTP 集成测试后重跑通过，没有放宽生产判断。

独立只读审查及 HTTP fixture 增量审查均未发现阻塞问题。仓库 230 个文件的密钥模式检查无意外命中，已排除唯一已知合成测试标记；此为模式检查，不等于全面秘密审计。
