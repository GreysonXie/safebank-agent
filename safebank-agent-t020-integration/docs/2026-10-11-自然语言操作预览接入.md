# 自然语言操作预览接入

2026-10-11，开发基线 608ff2e。扩展原 v0.7 工作树，保留原版本；不新增理财、卡片或任意 DAG。现有架构、表结构与 MyBatis 分层保持，新增 Java AgentPreviewService 复用银行业务服务。

## 当前实现

LangGraph 规划白名单新增 transfer_preview 和 revoke_preview。即时转账提交付款账户名称、收款人姓名/手机号/备注、整数分金额，Java 核对本人账户与收款候选；重名或账户不明时不生成卡。撤销只针对当前用户当前会话有效的已确认代扣查询快照中的明确服务，不跳过黄色查询确认。

每轮最多一个预览。操作 ID 由原 turn 与 operationKey 稳定派生；相同输入重放原回执，不重复创建。银行预览、工具回执处于同一短事务，失败不留下孤立资金动作。模型仍不能授权、提交、取验证码、修改风险级别或提供 userId/grant。预览不会改变余额、记账或撤销授权。

新预览请求会使同会话由本对话生成的旧未受理预览及其授权失效；改为重名对象而进入补问时，旧卡也失效。UNKNOWN/PENDING 原动作阻止新预览，须先核对原单。最近动作已执行后，含“改/换”的修订请求被拦截，不把修改解释为再次付款；这个判断是有限规则，不宣称覆盖所有口语修订表达。独立表单创建的动作不属于这组对话预览，不能宣称它们会随聊天改参自动取消。

预览事实仅投影必要的对象与金额，不把 payloadHash、授权或内部身份作为模型事实。Java 最终回答继续完整核验。动作状态用当前锁定读，防止 RR 旧快照把已取消卡当成待确认。查询/预览回调、回答验证和完成均按用户风险 guard→会话顺序，避免并发撤销与查询回执失效形成反向锁循环。沿用会话→轮次→工具回执的现有索引路径，不新增无索引全局回执锁扫描。

澄清等待保存原预览计划，补充备注时能承接金额/账户。离线 MockModel 增加明确标注的有限预览样例，咨询和否定问法不生成卡；它不是自然语言能力的真实模型验收证据。客户只询问能否取消、影响或建议时，仍走分析。

前端复用原操作卡：Java 回传真实当前状态，包括失效旧卡；聊天增加“核对待确认操作”入口，原左侧导航、业务区和右侧对话布局保留。确认和模拟强验证仍由原界面完成，聊天中的“确认”不构成授权。

## 明确局限

本阶段重点是即时转账和指定服务撤销的对话预览，不宣称已完成自然语言定时转账、AA、任意跨场景规划或真实银行接入。没有新增 DeepSeek 调用，因此新预览规划的真实模型语义质量仍待小批验证。模型对金额的理解必须由客户核对卡片，Java 只保证整数金额、归属、余额及风险规则正确，不能由此证明模型理解永远准确。

专门诱导转账处理、敏感输入遮罩、广泛口语修订和取消任务的对话协议还需后续完善。模拟 OTP 仍不是真实 MFA。此次完成执行桥梁不关闭安全自评中的模型语义与注入、真实验证和生产接入风险。
