# 验收结果记录模板

每次只填实际执行的案例，提交已脱敏副本；不附.env、密钥、CSRF、内部grant或数据库配置。

| 字段 | 填写内容 |
| --- | --- |
| 案例 | B01等；首次部署填WIN01 |
| 测试人及日期 | |
| 源码版本 | Git commit；ZIP说明下载日期 |
| 环境 | Windows版本、Docker Desktop版本、浏览器；部署问题填写 |
| 模式 | mock / 历史回答回放 / 新真实模型 / 真人体验；分别记录 |
| 完整输入顺序 | 保留原问题、追问、改口及操作卡点击顺序 |
| 预期结果 | 引用目标表，不临时降低标准 |
| 实际结果 | 回答是否切题、引用是否对应、卡片参数和状态 |
| 结论 | 通过 / 不通过 / 阻塞 / 未执行；不要把跳过记通过 |
| 证据 | 截图或脱敏自检/冒烟报告；不包含凭据 |
| 业务旁路核对 | 是否新增预览、授权、委托、流水；没有检查就填未检查 |
| 后续 | 缺陷编号、复现条件及复测版本 |

首次部署建议：生成本机配置→运行自检→启动→只读冒烟→刷新→`docker compose down`→`docker compose up -d`→再做冒烟；保留数据库卷，不使用`down -v`。不同冒烟会创建独立合成对话，不执行资金操作。

失败时保存原requestId供本机查单，不删除数据库或改编号绕过；公开问题记录不附内部凭证。自检通过只说明已检查环境条件；冒烟通过只说明免费账单和原请求重放链路，不代表三业务真实模型全部通过。
