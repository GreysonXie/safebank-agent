# SafeBank 源码检查修复验收 · 2026-10-28

截图中的失败项是 GitHub Actions 的 `source-checks`。本轮在当前分支完成本地修复与隔离验证，未提交或推送；旧提交的检查记录不会随工作区修改而改变。

## 失败定位

- 远程记录：[Team checks #22](https://github.com/GreysonXie/safebank-agent/actions/runs/40635396873)。对应分支为 `feature/workspace-management`，提交为 `d6543ac9912a2ee1ffe7c06faaf8f482d5184397`。
- 原工作流直接运行 `node --test src/test/js/*.test.cjs`，没有安装 `package-lock.json` 中的依赖。干净检出时，金融页面测试无法加载 `jsdom`。
- 安装依赖后，资源版本断言暴露了另一项差异：部分静态文件使用 CRLF，而其他文件在 Windows 检出时也会受 `core.autocrlf=true` 影响。页面资源版本按实际字节计算，Windows 工作区与 Git 导出的 Linux 源码因此可能得到不同 SHA-256。
- Actions 关于运行时弃用的提示属于警告，本轮没有扩大修改 Actions 版本。

## 修复

- `.github/workflows/team-check.yml` 在前端测试之前执行 `npm ci --ignore-scripts`，按锁文件安装依赖。
- 新增 `.gitattributes`，将 `src/main/resources/static/` 下的 CSS、JS、HTML 统一为 LF；同步规范化当前文件，并运行 `npm run version:ui` 更新页面资源内容版本。保留原有严格的内容哈希断言。
- 完整 Java 回归时还发现 `MyBatisMigrationRegressionTest.concurrentFailedOccurrencesReturnSameFailureInsteadOfConflict` 的屏障可能只有一条线程进入，从而偶发超时。改为协调两条线程在事务外的首次状态读取，确保它们在授权、提交前汇合，并避开事务内持锁的读取。保留同一个 action_id、余额不足、单条期次、零资金流水和单条拒绝审计等全部业务断言。

本轮没有修改生产 Java 业务逻辑，也没有调整资金授权规则。
