# 规划与回答契约修复及失败原题复验

2026-10-11。范围：上一轮六批24场景中的7个未交付问题，保留Java银行权限、资金执行、MyBatis与数据库结构。原版本留在6d46518；本次在v0.7开发分支改进，不覆盖归档版本。

## 改动与依据

1. 规划合同失配允许一次模型重写，使用稳定的同节点第二序号保存效果回执；预算不足三次时不启动该恢复，草稿重写继续计入同一回合额度。general不能携带tools，clarification仍受原合同约束，不静默改意图或工具。
2. 明确询问本人当前银行侧授权状态、指定服务收费周期/撤销边界时，要求规划包含mandate_receipt读取；已有确认回执时不重复要求确认。这只是查询规划要求，Java继续判定权限。一般规则、历史账单和其他用户请求不自动提升读取范围。
3. 事实筛选不把“别讲其他服务/续费日期”中的否定关键词当作扩大范围指令。用户原文仍完整传给模型，原银行回执不修改。
4. Java核验补充捕获到的否定句表达，例如“不代表近期已发生扣款”“无法直接告知转账成功”。同时使用横向空白和严格末尾匹配，拒绝把换行或下一句肯定执行归入否定范围；保留同句对象与已有状态绑定规则。
5. 草稿提示明确kind/answer合同；银行拒绝原因转成固定类型反馈，不将任意后端错误文本注入模型提示。允许事实查询后的正确general解释，不强迫伪造analysis引用。
6. 仅答案规范化兼容精确required_fields=[kind,answer]和空basis=[]。保持kind与正文，原供应商响应/usage不变，触发ANSWER_FIELD_NORMALIZED审计；缺kind、非空basis、不同schema提示、权限字段仍拒绝，规划合同不扩大。独立审查用原工具回执验证第5批两个规范化候选均通过Java。
