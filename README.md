## 模型配置

用户指定 `deepseek-v4-flash`、`https://api.deepseek.com`。密钥通过本机环境提供：

```powershell
$env:BANK_MODEL_BASE_URL='https://api.deepseek.com'
$env:BANK_MODEL_NAME='deepseek-v4-flash'
$secret=Read-Host '输入 DeepSeek API Key' -AsSecureString
$credential=[System.Net.NetworkCredential]::new('', $secret)
$env:BANK_MODEL_API_KEY=$credential.Password
Remove-Variable secret,credential
.\run.ps1 start
```

配置后重启。页面区分 OFFLINE_DEMO（有限规则演示）、MODEL_CONFIGURED（已配置但未验证）、CONNECTION_VERIFIED（本次进程已得到有效模型响应）；配置密钥不等于连接成功。API 使用 /chat/completions、function tools、thinking disabled；已验证本地HTTP契约、原4项真实联调，以及v0.3的60次真实查询/预览。真实Token与费用尚未采集。

模型可查询、生成预览或提出结构化联合任务；不能授权、提交资金或签发成功回执。离线联合任务通过表单创建。每轮最多6次生成请求、12次业务工具调用；每个通过数值核验的候选另用一次只读语义审核，最多再6次模型请求。单请求默认30秒，生成循环检查约90秒预算。请求耗时包含审核，不包含用户等待授权时间；授权等待可从 PREVIEWED/DEMO_USER_AUTHORIZED 审计时间核对。

## 故障实验

默认关闭。仅在本地实验显式启用：

```powershell
$env:SAFEBANK_FAULTS_ENABLED='true'
```

确认卡片可为当前 action_id 配置银行明确拒绝、执行后丢失响应、先受理后完成，以及查单不可用。故障保存到数据库，重启仍有效；不进入模型工具参数。

- 响应丢失：应用 UNKNOWN，银行可能已完成；先查单，重复提交不重复扣款。
- 先受理后完成：PENDING 不等于成功；后续执行约束不满足时返回已核验失败。
- 银行明确证明没有受理：恢复原动作供用户显式重试；不自动提交。
- 查单不可用：保持 UNKNOWN，依赖步骤不推进。

## 接口与模块

GET /api/session 创建固定u1演示会话并返回CSRF；所有POST携带Cookie和X-CSRF-Token。用户身份来自会话。

| 接口 | 用途 |
|---|---|
| GET /api/accounts、/statement?month=2026-09 | 账户与程序汇总账单 |
| GET /api/mandates、/recurring、/schedules、/audit | 本人代扣、周期候选、已登记计划、审计 |
| GET /api/recipients?query=张三 | 收款人候选，重名需澄清 |
| POST /api/transfers/preview、/mandates/preview、/schedules/preview | 生成未授权动作 |
| POST /api/actions/{id}/authorize | payloadHash、demoVerificationAccepted=true |
| POST /api/actions/{id}/submit、/cancel；GET /api/actions/{id} | 提交、取消草稿、查单 |
| GET、POST /api/workflows；GET /api/workflows/{id} | 创建、列表与恢复任务视图 |
| POST /api/workflows/{id}/resume、/cancel | version：当前任务版本 |
| POST /api/workflows/{id}/revise | version + request：新参数，不能回滚已受理动作 |
| POST /api/simulation/faults | actionId、submitMode、lookupMode；须启用实验 |
| POST /api/simulation/run-due | date：人工模拟日期触发 |
| POST /api/chat | text：受控工具对话 |
