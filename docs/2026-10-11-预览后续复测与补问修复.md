## 本轮发现并修正的问题

1. 批次 17：600 元卡生成且旧卡取消，但“已按你的要求更新转账预览”“已将转账预览中的收款人更新为…”被误判为已执行。新增捕获草稿回归先失败；仅在有对应当前预览证据时允许限定的预览更新措辞，不允许“已执行成功”“已完成转账预览”。45 项 Java 核验回归通过，原草稿在实际 Java 核验器免费回放通过。[回放证据](evidence/2026-10-11-preview-live/offline-replay-update.json)。
2. 批次 18：姓名/手机号与明确备注是可选检索条件，模型却在已经给出备注、付款账户和金额时重复补问。提示词明确任一合法条件可交 Java 核对，不由模型猜选候选；该批次没有成功生成旧 500 元卡，因此后续单独生成正确 600 元卡不能计为改参流程通过。
3. 批次 19：补问正文把“请补充收款人备注”与手写 500 元放在同一句。原本数字校验的整句删减将问题一起删掉，留下“已省略”的无效澄清。现在 clarification 不走整句删减，保留原草稿进入原有一次受限重写；每轮模型上限、Java 事实校验与权限边界不变。提示词要求没有预览金额事实时只问缺失项，不复述金额。新增运行回归先观察到仅调用两次、问题被删的失败，修正后 25 项 Python 相关检查通过，包括 MySQL checkpoint、一次重写限制和真实 Java 捕获回答核验。[Python日志](evidence/2026-10-11-preview-live/latest-python-regression.log)、[Java日志](evidence/2026-10-11-preview-live/latest-java-regression.log)。

批次 19 的最初自动断言只看 clarification 标志和卡片数量，未检查是否有具体问题，错误记录了通过。原始报告保留；最终核对明确加审阅纠正，实际为 2/3，而非 3/3。此后断言增加具体补参词、参数项及无“已省略”提示的检查。此检查仍不替代人工逐句评估。
