# 补参焦点与缺引用反馈

延续目标表真实缺陷：给同学转钱→补金额时反复索要姓名/手机号；储蓄回答全为手写数值、未引用事实，却先收到执行措辞错误。按既有业务和授权执行，零付费调用。

1. 对明确“给某对象转钱”的当前输入及同一未完成澄清链提供有界收款线索，只辅助规划，不认定已唯一匹配。不把线索当身份或授权，不从已切业务历史恢复。Java已返回歧义或用户改对象时不限制必要追问。对尚未查询就重复要姓名/手机号的已知表达，沿用一次预算内规划修正，由模型自然补问缺项，不替换为固定回答。
2. analysis缺事实引用时，先给准确的缺引用反馈和当前目录引用格式示例；不自动把手写数值换成引用、不放宽Java核验或增加修正次数。先检查凭证索取和风险要求。
3. 失败回归→实现→当前CI免费组及MySQL/捕获结果回放→一次独立审查→候选更新、目标表与GitHub同步。新模型效果仍未验，不追加模型费用。
