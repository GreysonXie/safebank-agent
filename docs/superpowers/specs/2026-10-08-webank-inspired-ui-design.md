## 目标

用户希望在架构审核前，参考赛题方微众银行官网的红蓝标志和滚动显现效果，使参赛产品的视觉更加协调。保留已经确认的左侧导航、中间业务、右侧对话布局，补充配色、组件和动效规则。

这是对公开官网的设计借鉴和本项目的产品判断，没有证据可据此推断评审人员的审美偏好或加分标准。比赛场景下更值得表达的是：业务信息易读、服务流程易理解、操作由客户确认、结果可核验。

## 官网实际观察

2026-10-08 使用 Playwright + 本机 Edge，只读访问 [微众银行官网](http<LOCAL_PATH> 插件未提供；网页文字抓取首次超时，改用真实浏览器，成功检查 1440 × 1000 视口和 scrollY=0/850/1700 的页面。

观察到：

- 标志采用红蓝组合；导航是白底，激活项以蓝色文字和细红线强调。
- 首屏有轮播视觉；正文大量留白，白色/浅灰区块交替，图文左右交错。
- 正文内容存在滚动后显现的处理，DOM 有 wow / fadeInUp30 类，样式中的该动画从 opacity:0、translateY(32px) 到 opacity:1、无位移；基础动画类定义 1s 时长，实际元素仍可能覆写。
- 页面 CSS 的导航与交互规则出现 #3A5ECF、#D80C18，另有 #1A4F99 和 #F5F7FA 等颜色。这些是本次抓取的网页色值，不定义为官方品牌手册标准色。
- 官网文案强调普惠、科技创新以及无障碍金融服务。设计借鉴应服务客户理解业务，而不是只复制装饰。

样式来源：[官网加载的 CSS](http<LOCAL_PATH> target/webank-reference/，仅作本地研究材料，未加入产品资源或 Git 提交。

## 颜色与视觉规范

| Token | 候选值 | 使用位置 |
| --- | --- | --- |
| primary | #3A5ECF | 发送、主要操作、焦点提示、导航与链接 |
| brand-red | #D80C18 | 自有 S 标识的小细节、导航激活短线；少量使用 |
| heading-blue | #1A4F99 | 品牌字与重要标题，可配深色正文 |
| page-background | #F5F7FA | 工作区背景 |
| surface | #FFFFFF | 对话、账单与操作内容表面 |
| selected-background | #EDF2FF | 激活导航、用户消息等轻量强调 |
| text | #0F172A | 正文、金额、必须核对的参数 |
| secondary-text | #526173 | 辅助说明；避免过淡灰字 |
| border | #E2E8F0 | 轻量分隔，不承担唯一状态提示 |

本地按相对亮度公式计算：primary 白底对比度约 5.70:1，brand-red 约 5.27:1，heading-blue 约 8.01:1，secondary-text 约 6.33:1；上述四色在 #F5F7FA 上也高于 4.5:1。实际组件仍需针对文字背景、禁用态及焦点单独验证。

保留 SafeBank 自有名称与 S 标识，增加红蓝细节；产品不使用微众银行官方标志或官方产品标识。所有截图和页面保留“合成数据演示 / 模拟资金与身份”的当前事实说明。

普通支出不是失败或风险，不能因为品牌红色就把支出总额和交易标成红色。收入、支出均使用清晰的深色数字；成功、失败、处理中、未知继续以文字和必要图形区分，不仅依靠颜色。

字体使用现有系统中文字体，无需新增网络字体。正文建议 14–16px、行高约 1.7；主标题 28–32px，金额 24–28px，说明不低于 12px。圆角约 8px，细边框与克制阴影；保持主内容和对话空间，避免大横幅挤占第一屏。

## 按现有页面落地

- 左侧六个入口保持；激活入口浅蓝底、深蓝文字及细红线。导航滚动和键盘焦点可见。
- 中间仍是当前选中的业务；账单保留收入/支出双卡、分类条、原始查询依据与明细。类别排序和金额由查询结果决定。
- 待确认操作与回执保留独立区域；对象、金额、时间、确认勾选和执行按钮的位置稳定。红色品牌装饰不包围确认按钮制造告警错觉。
- 右侧持续对话；用户消息浅蓝，助手消息冷灰，发送按钮蓝色。保留等待、失败手动重试、成功响应后刷新失败不重发需求、IME 和换行处理。
- 窄屏仍为顶部横向导航、业务内容在上、对话在下。对话输入不能被动效、固定横幅或弹出层遮挡。
- 初始没有账单时仍显示空状态，不预填模型回答或伪造账单。概念稿采用已有合成数据展示回答后的状态。

## 动效规则

| 场景 | 规则 | 目的 |
| --- | --- | --- |
| 非关键说明、工具介绍、明细标题首次滚入视口 | 8–12px 轻微上移 + 淡入，220–320ms；同组错开≤60ms，总等待≤400ms | 引导阅读顺序 |
| 切换导航后的内容过渡 | 120–180ms；保持数据可读，不移动关键参数及表单焦点 | 帮助确认视图切换 |
| 按钮悬停与按下 | 100–150ms 背景或边框变化 | 提供操作反馈 |
| 聊天等待、操作回执更新 | 状态文本及时更新，无反复滚动入场 | 传递真实状态 |

关键金额、交易行、授权勾选、执行按钮和回执终态不参与滚动隐藏或位移；新数据立即可读。首屏主要任务入口不等动画才可使用。用户往返滚动时不反复播放；后台刷新不把整屏重新隐藏；银行执行期间不播放庆祝或成功动画。

实现建议：现有原生静态前端使用 [IntersectionObserver](http<LOCAL_PATH> 观察非关键区块，CSS 只动画 opacity/transform；不引入整套官网动画库。默认内容可见，只有增强能力可用且用户允许动效时启用；JavaScript 或观察器不可用时正文仍可读。首次呈现后取消观察，避免重复播放。

## 审核与验收

审阅顺序：保留布局是否合适 → 红蓝候选配色与概念稿 → 动效范围 → 与后端架构分开的实施任务。UI 色彩与动效不依赖 MyBatis 迁移，不应混入同一个巨大改动。

实现后验收：

1. 在 1440/1024/768/390 宽度查看空状态、已查账单、待确认操作、失败与 UNKNOWN 回执。
2. 对照审核通过的视觉稿检查品牌、配色、字体、三栏比例、留白、金额可读性和输入区。
3. 正常动效、减少动效、键盘焦点、滚动往返、快速切换导航、查询刷新与 JavaScript 降级均检查。
4. 原有对话/表单/逐项授权/取消/原动作查单回归保持；动画不触发 API，不增加模型调用。
5. 通过拦截聊天响应和本地合成数据验证 UI，本次和后续纯 UI 验收不需要使用 DeepSeek。

当前仅完成官网研究、设计稿和概念生成，没有修改运行页面、数据库或 Java 业务代码。
