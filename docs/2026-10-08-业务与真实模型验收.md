# 新版真实模型与比赛业务验收（2026-10-08）

基线 b8069a9，当前已合并的 MyBatis 后端。用户批准先做小预算真实模型验证和核心业务验收。本轮没有修改生产行为、数据库或网页视觉，新增可重复执行的业务浏览器脚本和验收证据；所有资金操作只发生在三次独立、用完关闭的合成银行中。

## 结论

真实模型三组共 6 轮的自动断言通过：回答有业务事实、追问重点变化、跨月补查、收款人澄清，没有预览/授权/执行，账户不变。人工审查发现跨月退款对应关系证据不足，因此不能把 6/6 自动通过当作完整语义验收通过。

浏览器实际操作确认卡完成正常、部分失败、未知恢复三条核心流程；29 项针对业务的 Java 回归通过。当前模型连接已验证的新版本地入口为 htt<LOCAL_PATH> 8092/8093/8094 服务继续运行，8095 仍为离线候选。

## 真实模型与成本

调用总预算 24 次，包含生成和只读语义审核；每回合由服务端 modelRequestLimit 限制，评测失败立即停止，不批量重试。

首次在沙箱内创建服务时，TCP443 被操作系统权限拦截，首轮 MODEL_UNAVAILABLE，账户保持；评测立即停止并保留 6 次预留预算。套接字检查确认权限问题后，按已授权操作在沙箱外只重启本轮 8096 服务，重新评测三组。没有修改业务代码来掩盖连接失败，也没有触碰密钥输出。

- 成功供应商请求：17 次，其中生成 11 次、审核 6 次。
- 初始连接失败：1 次本地模型尝试，没有供应商 Token 回执。
- 即使失败仍按 6 次预留计，本轮保守记账 23/24；实际成功调用未越过预算。
- 供应商报告输入 142,989 Token、输出 1,983 Token，总计 144,972 Token；17 次均有完整用量。

## 人工审查与待改进

1. 跨月比较回答将 9 月退款直接认定为 8 月那笔购物的退款。当前接口只有交易 ID、商户、类别、金额、日期，缺少原订单/退款关联字段。金额相同、商户相关只支持可能对应，不能确认。应完善生成与审核的证据边界；需回归“同金额但不同订单”与“有明确关联字段”的两种情况。
2. 首轮出现一次数字核验拒绝后重新生成，17 次请求中有一笔额外生成。被拒原候选未保存，不能确认是不是误拒；需在安全的评测记录中保留脱敏候选和拒绝依据才能定位。
3. 跨月比较单轮输入累计较大，事实目录、历史与审核占主要输入。下一步按问题缩小事实目录，并保证大额明细、跨月计算和归属证据不丢失；先用本地脚本测上下文体积，再做少量有上限的真实复测。

本轮预算到此停止；没有为得到“全绿”反复重跑，也没有声称模型审核能替代人工审查。缺少用途/报价的进一步追问、恶意输入以及更多随机重复留给后续针对性验证。

## 实际浏览器与核心流程

使用 frontend-testing-debugging 工作流；没有可用 Browser 插件工具，采用本机 Playwright/Edge。脚本 `fixtures/business-workflow-qa.cjs` 启动本轮自己的 8097 Java 子进程，每个场景新建独立内存库、空密钥、显式本地故障模拟，场景结束关闭。聊天请求被禁止，没有模型调用。没有真实银行或现实资金。

| 场景 | 已核验结果 |
|---|---|
| 正常 | 查询账单 → 选择音乐/视频 → 三张卡分别勾选确认 → 撤销两项 → 登记每月 83 元计划；登记不改余额；模拟首期转入 83 元 |
| 部分失败 | 视频明确拒绝，只把音乐对应的 15 元用于计划；任务 PARTIAL_SUCCESS；首期只转 15 元 |
| 未知与刷新恢复 | 音乐已执行但响应丢失且查单不可用；任务 UNKNOWN、预计节省 0、只有原步骤；刷新保留原动作；恢复查单只记录一次执行、继续视频和 83 元计划 |
| 所有场景 | 确认按钮勾选前禁用；刷新保留任务版本/进度；计划登记不动资金；同一期运行两次复用原动作，两个账户余额只变化一次；无页面脚本错误 |

浏览器正常链路使用页面表单和确认卡；模拟故障配置、到期触发及余额核对使用同一页面会话的真实 HTTP API。使用项目原始演示种子（9 月支出 3,403 元），与真实模型六个月种子（9 月支出 5,369.33 元）隔离，不能混用金额。

本地回归执行：`./run.ps1 test -Tests 'WorkflowServiceTest,WorkflowRecoveryTest,WorkflowApiTest,ActionExecutionServiceTest,MyBatisWorkflowTest,MyBatisRecoveryTest,MyBatisMigrationRegressionTest'` → 29 项、0 失败/错误。文件重启恢复由 Java 临时 H2 文件测试覆盖；浏览器本轮的恢复是刷新恢复，不能混称进程重启。

脚本首次清理判定仅检查 exitCode，子进程收到信号退出时 signalCode 有值但 exitCode 为 null，导致错误报“未停止”。已修正脚本同时判断两者，重新跑三条场景均通过；没有修改生产逻辑。
