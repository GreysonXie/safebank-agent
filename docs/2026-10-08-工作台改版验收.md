# 工作台改版与上下文优化

用户确认第二版概念：左侧业务导航、中间业务内容、右侧持续对话；手机端改为业务内容在上、对话在下。保留 Java 后端与原生静态前端。

## 页面与交互

- 六个入口：对话助手、账单分析、代扣管理、储蓄任务、常用工具、实验与审计。账户按需展开。
- 查询依据与待确认操作放在业务区域，保留逐项授权、取消和原动作查单。
- 发送期间有等待状态并阻止重复发送；失败由用户手动重试；成功聊天后刷新失败不会重发原需求。
- Enter 发送、Shift + Enter 换行；中文输入法组合期间 Enter 不发送。
- 现有银行接口与表单参数保持，合成演示不连接真实银行。

## 后端

带横向空格的年月、日期正常通过事实核验。中文日字段要求明确“日/号”后缀，避免月份后面的金额被当作日期。未知日期和金额仍拒绝。

成功只读查询的完整结果保留在程序及 API 的 data/results 中；模型工具消息改为事实目录引用，减少与事实目录重复的账单数据。查询错误、预览、业务计算等结果保持原样。跨轮只使用当前保留的事实，缺失时重新查询。

这是重复上下文优化，没有进行新的供应商用量测量，不声称已节省某个百分比的 token 或费用。

## 验证

- Java 全量测试：145 项，144 通过，1 项付费联调跳过，0 失败、0 错误。
- 浏览器：Browser 插件未提供，采用 Playwright + 本机 Edge。fixtures/ui-workspace-qa.cjs 拦截所有聊天请求，并拒绝其他非 GET 请求，真实模型请求为 0。
- 检查 1440、1024、768、390 像素宽度，无页面横向溢出；导航、等待、失败重试、IME、换行，以及聊天成功后刷新失败的防重发均通过。
- 打包成功并更新已记录的 8093、8094、8092 本地实例；再次使用线上实际静态资源（SAFEBANK_UI_LIVE=1）运行浏览器回归，4 个拦截聊天请求，真实模型请求 0。原数据入口保持原数据库，新数据入口重启重新载入合成种子。
- 独立只读审查发现的日期吞金额和成功后刷新失败导致重发问题均已修复并回归。
