# 代扣回答聚焦优化

本阶段解决上次真实回答夹带无关已撤销服务、暴露 QUARTERLY 的问题。生产回答仍由模型围绕业务事实生成；不增加固定答案模板，也不改 Java 权限、金额核验和交易执行。

## 实现

- 草稿和一次重写共享相同事实筛选。用户明确点名服务时保留对应授权行、查询时间及其他工具依据；多个明确服务保留多行，同名多行保留歧义。
- 名单、整体合计、占比以及“其余／别的／一起”等问题保留整体范围。未知名称、无法确认名称边界和未明确对象的追问也保留原范围，交给模型澄清；不推断未知服务不存在。
- 去除具有对应稳定事实的重复历史别名；来源不同或没有对应事实的别名保留。原始回执和事实来源不改写，筛选不授予额外读取权限。
- 提示要求只回答所问对象，把收费周期用中文说明，避免无关服务举例；JSON 仍严格只接受 kind、answer。提示服从情况需要真实模型验证。

## 验证与结果

独立审查发现三项 Important：遗漏“其余／一起”造成误删、两字名称未识别、较长未知名称被子串匹配。补充测试先得到 4 个失败，再修复。最终 36 项相关离线回归通过，覆盖草稿与重写、整体范围、短名称、未知扩展名称、同名歧义、其他工具及引用合同。

本地网页到 Java、Python LangGraph 的两条免费接口回放均 HTTP 200：原季度服务问题返回季度 180 元及商户合同边界，不出现 QUARTERLY 或无关已撤销服务；继续询问明确月付合计返回 83 元。使用的是 mock，因此只能证明集成链路，不能据此宣称真实回答已改善。

以此前成功真实请求的合成业务回执测量，目录从 60 项／10,289 字符缩为 17 项／2,622 字符，减少 74.52%。这是事实目录字符数，不是完整请求 token 数或实际费用节省。

本轮供应商调用 0 次，两个付费预算文件逐字节不变。原账本 19 条、新阶段 5 条以及未知调用预留均保留，不重置预算。累计保守预留沿用此前 2.35 元。资金表只读核验见证据，网页保持 LANGGRAPH_MOCK。

## 后续边界

名称边界规则采用保守回退，可能少筛一些自然表达；优先保证比较和合计依据不被误删。R03/R10 的真实模型语义与相关性风险仍开放，下一小批真实验收应沿用原预算，检查是否仍出现无关内容及多余字段。
