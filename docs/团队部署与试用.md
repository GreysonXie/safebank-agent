# 团队部署与试用

优先用README的Docker入口。Java和Python在同一应用容器保持内部loopback认证；MySQL只在Compose私有网络可见，网页仅映射本机127.0.0.1。银行/Agent的DML账号与迁移账号分离，服务身份独立生成，不复用作者密码。

数据库卷和运行身份卷需一起保留；库为空才导入合成数据，重启不覆盖执行结果。没有对应身份的既有数据库会拒绝接管，先检查卷和配置，不直接删库。

## 四人分工

- Java队友：MyBatis、权限、事务、预览和回执。
- 队友一：账单、退款、大额和追问。
- 队友二：代扣周期、合同边界和取消咨询。
- 队友三：页面、操作卡、口语歧义及错误恢复。

先查后问、改口、只要结论、不要汇总、缺日期和对象同名都应覆盖。默认不提交资金动作，不把合成执行当作银行接入。

## 问题记录

填写提交版本、mock/deepseek、完整问题顺序、实际和期望回答、业务依据、截图与复现步骤；分别归类任务、安全和交互。错误记录HTTP状态和错误码，但不要附API密钥、内部token或数据库密码。

## 开发测试

Java21+Maven3.9运行mvn test；付费和MySQL专用测试默认不启用，开启需显式测试环境。Python3.12虚拟环境安装requirements.lock.txt，运行README中免费单元模块。

Runtime/MySQL测试需要SAFEBANK_AGENT_TEST_DB_CONFIG JSON（host、port、user、password），仅使用隔离测试实例；账号需创建/删除随机测试库。Java Oracle测试另需Java21和SAFEBANK_TEST_JAVA_CLASSPATH（Maven测试依赖classpath）。这些配置留在各自环境，不提交，绝不使用真实业务库。

权限、事务、Mapper或表变更先读AGENTS.md、CODING_STANDARDS.md及数据库设计，表变更单独迁移，不自动修复未知结构。
