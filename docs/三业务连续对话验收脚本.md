# 三业务连续对话验收脚本

使用同一会话依次输入每组内容；各组另建会话，不删数据库。逐轮记录版本、模式、问题、实际回答、追问次数、预览对象和状态，用[结果模板](验收结果记录模板.md)签收。mock、历史回放、新真实模型及真人体验分开记录；以下是固定验收标准，不是已完成真实生成的声明。

## A：账单追问与简洁表达（B01—B04）

| 轮次 | 输入 | 必须观察到 |
| --- | --- | --- |
| 1 | 分析2026-09账单 | 查询指定月份，金额来自银行；不凭空补用途 |
| 2 | 最大一笔支出是什么？ | 同月份，引用Java完整账单最大支出；并列不能擅选唯一；不把退款或内部转账列入 |
| 3 | 这笔能确定用途吗？ | 承接上一轮对象；不能仅凭名称确定真实用途，说明需核对哪些凭证 |
| 4 | 哪些退款能确认，能直接抵扣支出吗？ | 区分入账/支出口径，不捏造与订单的关联 |
| 5 | 只说最值得关注的三点，不要逐笔复述 | 随表达要求组织回答；不重问月份，不全文重播或凑未经核验的统计 |

失败包括：每轮同一模板、缺依据却推断用途、退款抵扣口径混乱、无必要的月份追问。记录实际长度和信息点，不仅看HTTP成功。

## B：代扣咨询、预览与暂缓（M01—M04）

先在业务页明确确认“查询本人银行侧代扣”，只为该查询授权；记录其回执。普通试用不执行撤销。

| 轮次 | 输入 | 必须观察到 |
| --- | --- | --- |
| 1 | 季度安全服务180元是每月扣吗？ | 读取有效查询快照，区分季度约定和每月折算，不猜已发生扣款 |
| 2 | 撤销银行代扣，是不是就退订并退款了？ | 区分银行授权、商户合同、退款，不主动生成撤销卡 |
| 3 | 只生成音乐服务撤销预览，先不执行 | 准备指定服务的待确认卡，不授权或执行 |
| 4 | 先不办 | 退出办理补参，不新建/更新预览，不继续追问操作参数或催促确认 |
| 5 | 只解释合同边界，不要重复金额 | 回答当前咨询，不恢复上一轮办理意图，不重报无关金额 |

“先不办”不是银行撤销回执，也不自动取消已有卡。若旧卡仍存在，说明其实际状态；需要取消时在业务页单独核对，不能凭聊天声称已取消。

## C：连续补参、改金额与切业务（T01—T04）

| 轮次 | 输入 | 必须观察到 |
| --- | --- | --- |
| 1 | 给同学转钱 | 只问缺少的金额/付款账户；不自填参数 |
| 2 | 500元 | 承接收款检索词“同学”，只补问仍缺的付款账户 |
| 3 | 日常账户 | 保留前两轮片段，准备500元预览；Java解析对象，无授权和流水 |
| 4 | 改成600元 | 最新金额优先，保留明确的账户/对象，旧卡失效、新卡参数正确 |
| 5 | 换个问题，分析2026-09账单 | 切到账单查询，不再生成转账卡；切业务不等于取消旧卡 |
| 6 | 再改成700 | 已切业务，不能靠已过期的澄清片段擅自恢复转账对象；必要时问清要修改什么 |

另以新会话检查“给张三转500元”的同名歧义，不替用户选人。对UNKNOWN或已提交原动作，不通过修改参数另建操作。

## 本批工程覆盖和边界

C组六轮、独立“给同学转钱→先不办”的两轮流程已有免费候选实际HTTP核验；以[最新阶段记录](2026-10-15-业务切换后改金额验收.md)的实际结果为准。A组部分步骤已有历史回答及脚本证据，B组本批未重新真实生成整组。C组全程的真实语义、复合暂缓句、口语同义改写及回答质量仍需新真实模型/真人签收，不因有限mock能跑而标通过。

工程实现只为连续澄清保留最多4段、总计4000字符的原用户片段，超限丢较早的整段；历史不是授权、身份或银行事实。正常新轮次清空该暂存上下文。片段不足时应重新补问，不能声称记住无限会话；风险hold与原银行动作状态不会因此清空。

现有6元累计上限与未知预留继续生效；脚本不授权新增真实模型费用。真实验收应先确认明确预算并记录调用/用量，遇未知状态沿原请求核对。
