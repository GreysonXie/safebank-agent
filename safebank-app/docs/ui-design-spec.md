## 0. 产品与信息架构概览

### 0.1 产品定位

SafeBank 是一个**本地合成数据的个人银行助手**（页脚文案：`SafeBank v0.7 · 合成资金与身份 · 本地演示`）。核心体验是"三栏工作台"：左侧业务导航、中间业务数据与操作卡片、右侧常驻对话助手。模型只做查询与"操作预览"，任何资金动作都必须由用户逐项勾选确认后执行。

### 0.2 一级导航（6 个目的地）

| # | 导航文案 | 视图 key | 页面标题 | 页面副标题 | 说明 |
|---|---------|---------|---------|-----------|------|
| 1 | 对话助手 | `chat` | 对话助手 | 从你的问题开始，结合业务数据继续追问。 | 与右侧对话面板同源，用于宽屏下的引导卡片入口 |
| 2 | 账单分析 | `statement` | 账单分析 | 先看清账单，再决定下一步。 | **Web 默认打开的页面**（`selectView('statement')`），但默认高亮在第 2 项 |
| 3 | 代扣管理 | `mandates` | 代扣管理 | 核对授权与扣费周期，撤销前逐项确认。 | 查询代扣必须先"确认查询范围" |
| 4 | 储蓄任务 | `savings` | 储蓄任务 | 把已确认的计划拆成可核验的步骤。 | 含"定时储蓄"表单 + "联合任务"工作流 |
| 5 | 常用工具 | `tools` | 常用工具 | 填写对象与金额，先生成操作预览。 | 转账预览 |
| 6 | 实验与审计 | `audit` | 实验与审计 | 查看合成银行记录与模拟验证结果。 | 文案自述"仅用于本地实验"，属开发者/演示入口 |

> 注意：`index.html` 中导航顺序是「对话助手」在前，但初始 `aria-current="true"` 落在「账单分析」上；`selectView('statement')` 在脚本末尾执行。Android 的 start destination 需明确决策，见 §2.4。

### 0.3 双栏内容区的固定结构

业务区（`#business-content`）自上而下固定为：

1. `PageHeader`：`h1`（页面标题）+ `p`（副标题）+ 右侧主按钮「查看账户」
2. 账户面板（默认折叠）：账户卡片网格
3. 当前视图（6 选 1）
4. **「待确认操作与回执」面板**（所有页面共用，永远在最下方）
5. `footer` 版本信息

右侧对话面板（`aside.chat-panel`）在所有页面常驻：模式徽章 → 模型信息 → **上下文记忆区** → 消息列表 → 建议 chips → 输入框 → 快捷提示 → 状态行 → 重试按钮。

## 1. 设计令牌（Design Tokens）

### 1.1 色板来源与层叠关系（必读）

- 第 1 层 `styles.css`：早期"墨绿银行"主题（`--green:#176c57`、底色 `#f4f7f5`），**大部分已被覆盖**，但保留了全部布局与尺寸。
- 第 2 层 `theme.css`（`?v=logo2`，后加载）：红/蓝工作台主题，重定义 `:root` 变量并覆盖按钮、卡片、气泡、徽章、账户卡、通知条等颜色。
- 因此 **最终 UI 是"蓝 + 红点缀 + 冷灰"**，不是绿色。特别注意 `theme.css` 把 `--green` 重新指向主色（`--green: var(--primary)`），即**旧的"绿色语义"现在实际渲染为蓝色**。

### 1.10 动效

| 名称 | 规格 | 触发 |
|------|------|------|
| 按钮背景过渡 | `background .15s`（默认 ease） | hover / 状态变化 |
| 入场揭示 `.reveal-once` | `260ms ease-out both`，`opacity .65→1`，`translateY(8px)→0` | IntersectionObserver 阈值 `0.15`，只播一次；获得焦点时立即取消动画 |
| 滚动 | 最终为 `auto`（`styles.css` 后段覆盖了 `smooth`），个别操作仍 `scrollIntoView({behavior:'smooth'})` | 跳转到操作卡 / 输入框 |

| 手机导航 | 无 | — |
| `prefers-reduced-motion` | 关闭全部 transition / animation / smooth scroll；揭示动画完全不添加 | 系统设置 |

### 2.4 手机端推荐形态

#### 2.4.1 结论：底部导航 5 个 tab，对话作为独立整页

| tab | 文案 | 图标 | 内容 | 说明 |
|-----|------|------|------|------|
| 1 | 对话 | 气泡 | 对话整页（消息 + 上下文 + chips + 输入） | 与 Web 右侧面板 1:1 |
| 2 | 账单 | 柱状图 | 账单分析页 | 默认 tab（与 Web 默认视图一致） |
| 3 | 代扣 | 银行卡 | 代扣管理 | 首次进入需"确认查询范围" |
| 4 | 储蓄 | 闹钟 | 定时储蓄 + 联合任务 | 列表较长，独立 tab 合理 |
| 5 | 更多 | 宫格 | 常用工具、实验与审计、关于/版本 | 低频入口收纳 |

> 若产品坚持「常用工具」必须一级可达，则采用 **对话 / 账单 / 代扣 / 储蓄 / 工具** 5 tab，把「实验与审计」从 tab 移到「更多/设置」内并加调试开关（该页文案已自述"仅用于本地实验"）。两种方案都**不要做 6 个 tab**。
>
> 启动落点：Web 默认落在「账单分析」，建议 Android 与之一致（首屏 = 账单 tab，见 §8 第 16 条）；若产品要「对话优先」，则把对话设为默认落点，导航顺序保持列表所示。

**为什么对话不做浮动 FAB：**

1. **对话是主模式，不是瞬时动作**：它承担上下文记忆（月份、比较月份、待补参数）、证据追溯、回执播报、建议追问，是一个长生命周期页面，FAB 无法承载"输入框 + 滚动位置 + 忙碌锁"。
2. **FAB 会压住关键操作**：业务页底部正是「待确认操作卡」的「确认并执行 / 取消操作」按钮区，FAB 悬浮在同一热区，误触风险与遮挡风险都高。
3. **状态需要常驻可视**：聊天忙碌锁（`chatBusy`）、未完成原请求（`核对原请求`）、状态行 `#chat-status` 都必须可见；FAB 收起后这些状态无处呈现。
4. **一致性**：Web 的 6 个 `data-view` 都是平级页面，对话只是其中之一；改成 tab 保持心智模型一致，且 `查看代扣` 这类跨页跳转仍可 `selectView`。
5. 若确实需要"处处能问"，可在业务页 AppBar 右侧加一个 **「继续对话」文字按钮**（仅当存在活动会话时显示），不要用 FAB。

#### 2.4.2 跨页的「待确认操作与回执」

Web 中该面板常驻在每个页面底部。手机端把它改为**独立路由**：

- 入口：TopAppBar 右侧徽章按钮「待确认 (N)」（N = `AWAITING_AUTH` + `AUTHORIZED` 数量），以及对话页回答后出现的「核对待确认操作」气泡按钮。
- 呈现：优先独立整页（`Scaffold` 全屏），**不要用 BottomSheet**——红色等级操作需要勾选、OTP 输入、风险说明和长文案，Sheet 高度与键盘会互相挤压。
- 历史回执：同页底部可折叠「历史记录 · 已完成或已取消（N 条）」。

#### 2.4.3 手机端页面骨架与尺寸

| 区域 | 规格 |
|------|------|
| 状态栏 / 导航栏 | edge-to-edge，`WindowInsets` 处理；底部导航上方预留 IME 内边距 |
| TopAppBar | 64dp（M3 small），左：页面标题（20sp/600）或返回；右：账户入口 + 「待确认 (N)」 |
| PageHeader 卡 | 保留 Web 的"白卡"观感：外边距 16dp、内边距 16dp、圆角 10dp、描边 1dp；标题 26sp/700、副标题 13sp |
| 账户区 | 单列卡片，间距 12dp；点击「查看账户」展开（默认折叠） |
| 内容区 | 左右 16dp，卡片间距 16dp（同面板 18px 的节奏取 16dp） |
| 底部导航 | M3 `NavigationBar` 80dp；图标 24dp；label 12sp；激活指示器 `#EDF2FF` + `#1A4F99` 图标/文字；品牌红仅用于 Logo 斜杠 |
| 对话页 | 消息列表 `weight(1f)` + `reverseLayout=false` 自动滚底；输入区底部对齐、`imePadding()`；输入框最小 48dp、最多 4 行后内部滚动 |

#### 2.4.4 横竖屏

- 竖屏：上述单列。
- 横屏（高度 <480dp）：对话整页改为"列表 + 输入"上下比 1:1，输入区不折叠；待确认操作卡整页滚动，风险区与按钮不并排。
- 平板横屏：`840dp` 以上双栏；对话列固定 360dp，业务列表可 1–2 列（账户卡 2 列、其余单列）。

### 3.6 待确认操作卡（Action Card）

单张卡片的**固定结构顺序**（顺序即无障碍阅读顺序）：

1. **错误条（可选，置顶）**：`.risk-error`，`role="alert"`、可聚焦、自动获得焦点；文案 `错误信息` + 若存在 `retryAt` 追加 ` · 可重试时间 2026/10/27 14:30:00`
2. **标题行**：`h3` 操作类型 + 状态徽章 `.status`
   - 类型文案：`TRANSFER`→转账操作；`REVOKE`→撤销银行侧代扣；`SCHEDULE`→创建定时转账；`QUERY_MANDATES`→查询本人银行代扣
3. **下一步提示** `.action-next-step`（`role="status"`，13px，左侧 3px 蓝灰竖条）：
   - `AWAITING_AUTH`：请先核对以下信息，再勾选确认。聊天中的确认不会执行操作。
   - `AUTHORIZED`：授权已记录，尚未提交。请核对最新状态后继续。
   - `CANCELLED`：本操作已取消。
   - `VERIFIED_SUCCESS`：对应回执文案（见 §3.7）
   - `VERIFIED_FAILED`：本操作未完成，请展开详情查看原因。
   - 其他：请先查询原操作的最新状态，勿重复创建相同操作。
4. **参数列表 `dl`**：两列 `90px / 1fr`，12px，`dt` 颜色 `#526173`，`dd` 可任意断行。字段按存在性渲染：
   - 来源账户、收款对象（优先展示 `recipient_label`）、金额、单期金额、手续费
   - 首次日期、结束日期、执行规则（`每月 N 日 · Asia/Shanghai`）
   - 代扣商户、影响（`scope`）
5. **折叠「查看操作详情」**：操作编号、回执编号、状态说明（`error_code`）
6. **风险分层卡** `.risk-level`：
   - 标题：绿色 · 可自动查询 / 黄色 · 需要明确确认 / 红色 · 需要验证后确认
   - 正文：RED → `本次预计日累计 ¥1,234.00，超过 ¥1,000.00，需补充验证。`；其他 → `核对本次操作范围、对象与参数后确认。`
   - RED 且 `verificationMode = LOCAL_DEMO_ONLY` 追加小字：本地合成验证演示
   - ⚠️ CSS 仅给 `.risk-red` 独立配色，GREEN/YELLOW 与默认同为蓝底（见 §8）
7. **确认勾选**：`复选框 + 我已核对本次参数，并明确确认操作`，整行可点，`margin-top:16px`
8. **RED 专属验证区**（`status ≠ AUTHORIZED` 时）：`发起验证` 按钮 → `一次性验证码` 输入（数字键盘、6 位、`autocomplete=one-time-code`、初始禁用）→ `校验验证码` 按钮（初始禁用）→ 状态行
   - 初始状态行：先发起验证，再从独立本机验证台取得演示码。
   - 发起后：`挑战编号 {id} · 到期 14:30:00`，输入框启用并聚焦
   - 校验通过：清空输入、取消勾选、要求重新勾选；状态行变为「验证已通过。尚未授权或执行，请再次核对并勾选确认。」
9. **按钮行**：`刷新风险条件`｜`确认并查询` 或 `确认并执行`（primary，默认禁用）｜`取消操作`｜`查询最新状态`
   - 按钮行 `gap:8px`、可换行、上边距 16px、每个按钮 `min-height:44px`
10. **故障实验面板**（仅 `faultsEnabled`，折叠）：实验故障设置（仅当前动作）、提交故障下拉（正常 / 银行明确拒绝 / 执行后丢失回执 / 先受理后完成）、同时模拟查单不可用、应用故障设置

| 条件 | 说明 |
|------|------|
| 勾选框已选中 | `checkbox.checked` |

**其他规则**

- 同一 `action_id` 只保留一张卡（重新渲染时替换）。

### 3.7 回执卡与回执文案

回执 = 操作卡的终态形态（`VERIFIED_SUCCESS` / `VERIFIED_FAILED` / `CANCELLED`）+ 对话气泡里的回执播报 + 历史记录区。

回执文案矩阵：

| 条件 | 文案 |
|------|------|
| 非成功状态 | `${状态标签}。请以查单结果为准，勿重新创建相同动作。` |
| `QUERY_MANDATES` 且成功且返回数组 | 本次代扣查询已完成；查询没有转账或记账。 |
| `QUERY_MANDATES` 且成功但非数组 | 这是原查询回执，重新查询需再次确认范围。 |
| `SCHEDULE` 成功 | 定时计划已登记，尚未发生转账。 |
| `REVOKE` 成功 | 银行侧代扣已撤销，商户合同状态未知，余额没有因此增加。 |
| `TRANSFER` 成功 | 转账已完成，并核验双边账务分录。 |

回执附带副作用：查询代扣回执会把 `confirmedMandates` 落地并重渲染代扣列表；撤销成功回执会把对应代扣状态改为「已撤销」。撤销成功同时弹 toast：`代扣查询已确认，可回到右侧对话继续询问收费周期或取消事项。`（查询场景）与状态行 `查询已确认，请在对话中继续提问。`

## 4. 页面规格

> 六个页面共享：PageHeader、账户面板、待确认操作与回执面板。以下只描述各页**独有**部分。状态统一口径：**加载态**（初始化 / 请求中）、**禁用态**（`appReady=false` 或请求中）、**错误态**（toast + 行内错误）、**空态**（见 §3.5）。

### 4.1 对话助手

**组成（自上而下）**：引导卡（`从你的问题开始` + 说明 + `开始对话` 按钮）→ 后续所有内容都在右侧对话面板。

**引导卡**：`h2 从你的问题开始`；说明 12px；按钮「开始对话」点击后滚动到输入框并聚焦。

**右侧对话面板结构**：标题行（`对话助手` + 模式徽章）→ 模型信息（11px）→ 上下文记忆区 → 消息列表 → 建议 chips → 输入区 → `Enter 发送 · Shift + Enter 换行` → 状态行 → 「核对原请求」按钮。

**交互**

| 行为 | 规则 |
|------|------|
| 发送 | 点击「发送」或按 Enter（Shift+Enter 换行；中文输入法组合中不发送） |
| 输入限制 | `maxlength=4000`；`rows=2`；空文本不发送 |
| 忙碌锁 | 请求进行中：发送按钮 disabled、所有 chips disabled、`清空对话草案` disabled、表单 `aria-busy=true`、状态行「正在处理问题并核对数据，请稍候…」 |
| 新问题冲突 | 已有未完成原请求时发送不同问题 → **不覆盖原请求**，把新问题留在输入框，状态行提示「上次请求尚未完成，请先核对原请求。新问题已保留在输入框，不会替换原请求。」，显示「核对原请求」 |
| 恢复原请求 | 点击「核对原请求」重发**原始文本**（不会自动重发） |
| 长时间处理 | 收到 `CONTEXT_PROCESSING` / `AGENT_RECONCILING` 时最多轮询 25 次、间隔 2s，状态行「正在理解问题并核对业务数据，等待原请求结果…」；单次 HTTP 超时 110s |
| 回答成功后 | 追加助手气泡 → 渲染查询依据到账单页 → 渲染动作卡 → 追加证据折叠 → 若有待确认动作追加「核对待确认操作」按钮 → 清空状态行 |
| 已收到回答但渲染失败 | 状态行「已收到回答，但页面更新失败：{message}。请刷新页面核对任务和回执。」 |
| 无回答 | 状态行「本次未获得回答：{message}」+ 显示重试；按错误码处理上下文（冲突/过期） |
| 清空草案 | 需有会话；清空消息、插入确认消息；不影响已确认动作与回执 |

**状态**

- 加载：初始化阶段徽章「正在建立会话」；发送后状态行 + 按钮禁用。
- 禁用：`appReady=false` 时所有输入与 chips 禁用，点击外层操作提示「正在恢复业务会话，请稍候。」
- 错误：上下文不可用（`NOT_FOUND` / `CONTEXT_EXPIRED`）→ 状态行「上下文已不可用，请重新提出问题；原动作仍从历史回执核对。」；页面恢复时「原对话不可用或已过期。新问题会建立上下文，已有银行动作请从历史回执核对。」；`CONFLICT`/`CONTEXT_INTERRUPTED` → 状态行「{message}。请核对最新状态后再提出新问题。」
- 空：仅欢迎语一条助手消息：`欢迎进入 SafeBank。账单可以直接提问；查看代扣请先确认查询范围，再分析收费周期。银行操作须核对预览并逐项确认。`

### 4.2 账单分析（默认页）

**组成**：PageHeader（`账单分析` / `先看清账单，再决定下一步。` / `查看账户`）→ 账户面板（折叠）→ 面板「查询依据」+ 右侧说明「随对话中的查询更新」→ 结果块区 → 待确认操作与回执 → 页脚。

**交互**

- 页面本身**没有查询按钮**：数据只能由对话触发（提示用户发送「分析2026-09账单」）。这是产品的核心设定，Android 不要额外加"查询账单"按钮，否则与"助手驱动"的模型冲突。
- 结果来自 `/api/chat` 的 `data` / `results`，多份结果会依次追加为多个结果块。
- 交易明细折叠依据条数决定默认展开（≤6 展开）。
- 点击「查看账户」展开账户网格（默认隐藏）。

**状态**：空态（未查询）；错误（结果块内 `.result-error`）；加载（对话忙碌时无骨架，仅状态行提示）。

### 4.3 代扣管理

**组成**：面板「银行侧代扣」+ 说明「仅撤销银行侧扣款授权；不会自动退款，商户合同状态未知。」→ 代扣列表。

**未查询（默认）**：说明「读取本人银行侧代扣列表前，请确认查询范围。」+ 按钮「确认查询范围」→ 生成查询意图卡（`查询本人银行代扣`）并滚动到待确认区。**必须先在待确认区勾选确认**，回执落地后列表才出现。

**已查询**：每行 `商户`（主）+ 小字 `¥金额 · 按月 · 银行侧授权有效`；`ACTIVE` 行右侧按钮「预览撤销」→ 生成撤销预览卡（`撤销银行侧代扣`）。列表底部再追加「重新查询」按钮（再次走确认流程）。

**列表为空**：本次查询没有返回银行侧代扣授权。

**查询成功后的引导**：提示「查询已确认。可继续分析，或先生成撤销预览；预览不会改变授权。」+ 两个追问按钮：
- 分析收费周期 → 发送「说明当前代扣的约定收费周期，区分按月、按季度和未确认的周期。」
- 核对有效月付 → 发送「只看目前明确月付的有效授权，列服务及金额，不要把已撤销的算进去。」

**状态**

- 加载：按钮在请求中禁用（`perform` 包装）。
- 错误：toast 显示后端 message；查询意图与对话锁冲突时提示「请等待当前对话请求完成，或恢复原请求后再查询代扣。」
- 空：见上。
- 撤销成功后：该行状态变「银行侧授权已撤销」且不再显示「预览撤销」。

**计费周期与状态文案**：按月 / 按季度 / 按年 / 周期未确认；银行侧授权有效 / 银行侧授权已撤销 / 银行侧状态未确认。

### 4.4 储蓄任务

两个面板：**定时储蓄**（表单）+ **从账单到储蓄的联合任务**（长表单 + 任务列表）。

**定时储蓄**：`每月转入旅游账户（元）`、`首次日期`、`结束日期`、`生成定时任务预览`；提示「每月固定日 1—28 日，最长一年。创建任务不会立即扣款。」提交后生成定时转账确认卡（`创建定时转账`）。

**联合任务面板**：标题 + 右侧说明「逐项确认 · 可恢复 · 有版本记录」+ 长说明（节省额不是余额增加，也不代表商户合同终止）+ 表单（§3.9.3）+ 任务列表（§3.13）。

**交互细节**

- 勾选代扣需要**主动选择**；未选提交 → 错误提示「请明确选定至少一项月度代扣」（toast）。
- 保存新版本：以当前 `version` 提交，成功后刷新整个任务列表；原待确认项失效。
- 取消后续任务：提交 `version`，刷新后还会重新拉取动作卡。
- 查单并继续：`resume` + 刷新。
- 查看动作：拉取单条动作并渲染到待确认区。

**状态**：任务列表为空时不显示占位（仅表单）；`aria-live=polite` 使新增任务可被读屏播报；计划懒加载失败只在折叠内提示，不影响页面。

### 4.5 常用工具

单面板「准备一笔转账」+ 三字段（§3.9.1）+ 提示「演示单笔限额 ¥10,000。重名联系人不会由系统自动猜选。」

**交互**：提交 → `POST /transfers/preview` → 生成「转账操作」待确认卡（状态 `待确认 · 尚未执行`），**页面不跳转**，用户需到下方待确认区确认；建议 Android 在生成后主动滚动/提示到卡片（Web 的对话路径会自动滚动，表单路径不会，属可改进点）。

**状态**：空表单（金额为空）；校验错误（toast）；提交中（按钮禁用）；成功后卡片出现在待确认区。

### 4.6 实验与审计

**组成**

1. 模拟卡（`simulation`）：`定时任务模拟验证` + 说明「在指定模拟日期触发已授权任务；重复触发同一期不会重复扣款。该入口仅用于本地实验。」+ 已登记列表 + `模拟执行日期` + `验证到期任务`
2. 折叠「查看结构化审计事件」+ JSON

**交互**：验证后对每个结果渲染动作卡；toast「已核对 N 个到期操作；请查看回执。」或「该日期没有到期任务。」随后刷新账户/计划/任务。

**状态**：已登记列表为空 → 该区域空白（无空态文案）；JSON 为空时 `pre` 为空。

**手机端建议**：默认折叠、置于「更多」内，并要求 debug 开关；不要把审计 JSON 作为主视图。

### 4.7 待确认操作与回执（跨页常驻面板）

**组成**：标题「待确认操作与回执」+ 右侧「操作前逐项确认」→ 待确认卡列表（新卡置顶）→ 历史记录折叠。

**空态**：`暂无待确认操作` + 小字说明。

**状态**：无卡片且无空态时补「暂无待确认操作。已完成记录可在下方展开查看。」；历史折叠在 0 条时隐藏。

**初始化**：页面加载时用审计日志回填最近 12 个动作卡（终态卡直接进历史）。

### 5.10 拼接规则与片段

Web 用 `textContent` 逐段拼接，Android 应改为资源字符串 + 格式化参数，以下为拼接片段与顺序：

| 场景 | 片段顺序 |
|------|---------|
| 账户卡 | `{label}` + ` · 合成账户` |
| 代扣行 | `{商户}` + `{¥金额}` + ` · {周期}` + ` · {状态}`，以 ` · ` 连接 |
| 周期候选行 | `{商户}` + ` · ` + `{N}` + `次 · ` + `{¥min}` + ` 至 ` + `{¥max}` |
| 已登记行 | `已登记：每月 ` + `{N}` + ` 日 · ` + `{¥金额}` + ` · 首次 ` + `{日期}` |
| 任务摘要 | `账单 ` + `{月份}` + ` → ` + `{收款人}` + ` · 预计月度节省 ` + `{¥金额}` + `（仅计本任务已核验撤销）` |
| 步骤行 | `撤销 ` + `{key 去前缀}` + ` · ` + `{状态}` + ` · v` + `{版本}` + 可选 ` · {errorCode}` |
| 风险 RED | `本次预计日累计 ` + `{¥金额}` + `，超过 ` + `{¥1,000.00}` + `，需补充验证。` |
| 状态行（冲突） | `{message}` + `。请核对最新状态后再提出新问题。` |
| 错误条 | `{message}` + 可选 ` · 可重试时间 ` + `{本地时间}` |

**金额格式**：`Intl.NumberFormat('zh-CN', {style:'currency', currency:'CNY'})` → `¥1,234.56`（无空格、两位小数、千分位）。传入前以"分"为单位除以 100。

### 6.5 图标替代方案

1. **依赖**：`material-icons-extended`（`androidx.compose.material:material-icons-extended`）能覆盖 §3.1 的建议名称；该包体积大，但 R8 会裁掉未用图标，release 可接受。
2. **更贴近原稿**：原图标是 1.8dp 描边、圆头、无填充，Material 图标是填充式。若要 1:1 还原，建议自绘 6 个 24dp `ImageVector`（路径可直接取自 `index.html` 的 `path d`），stroke 1.8dp、`StrokeCap.Round`、`StrokeJoin.Round`、`strokeAlpha=1f`、无填充。
3. **语义替换**：`储蓄任务` 语义上更适合 `Icons.Outlined.Savings`（存钱罐），形状更接近 `Icons.Outlined.Alarm`（闹钟）；建议用 `Savings` 并配文字标签，避免"闹钟"造成"提醒"误解。
4. **contentDescription**：导航项一律用中文标签（与 §5.1 一致）；纯装饰图标（导航指示条、品牌斜杠）设 `null`。底部导航已有文字标签时，图标可 `null` 以免重复播报。

### 6.7 动效与降级策略

| Web 动效 | Compose 对应 | 降级 |
|---------|-------------|------|
| `button` 背景 `.15s` 过渡 | 用 M3 `ripple` 替代（按钮配色固定，不需要背景过渡） | 系统动画关闭时 ripple 自动禁用 |
| `.reveal-once` 260ms，位移 8px + 透明度 .65→1 | `AnimatedVisibility(enter = fadeIn(tween(260)) + slideInVertically(initialOffsetY = { 8.dp.roundToPx() }))` | 只用于"新插入"的消息/卡片，**不要**做滚动触发的 reveal（LazyColumn 里会重复触发且浪费） |
| `scrollIntoView({behavior:'smooth'})` | `LazyListState.animateScrollToItem` | 动画关闭时用 `scrollToItem` |
| toast 6500ms | `SnackbarHostState.showSnackbar(duration = Long)` 或自定义 `delay(6500)` | 无障碍下可延长，不缩短 |
| `prefers-reduced-motion` | Compose 自动读取系统 `animator_duration_scale`；`LocalMotionDurationScale` 可读 `scaleFactor`，为 0 时直接跳过 | 不要用 `InfiniteTransition` 做常驻动画（本项目无） |

时长上限建议 **≤300ms**；同一屏幕同时最多 1 个入场动画；列表批量插入只对首项做动画。

### 6.8 状态与数据建模建议

- 页面状态：`Loading`（初始化中，禁用手势入口）、`Ready`、`InitFailed`（徽章"连接失败"+ 重试）。
- 对话状态：`Idle` / `Sending`（忙碌锁）/ `PendingOriginal`（有未完成原请求 + 可重试文本）/ `ContextInvalid`。
- 动作卡状态机：以服务端 `status` 为准，本地只维护"勾选 / 验证凭据 / 错误条"三份 UI 态；终态卡迁移到历史列表。
- 单一事实来源：`accounts`、`mandates`、`workflows`、`actions`、`audit` 各自独立仓库；`refresh()` 并发拉 4 个接口后整体刷新（Android 用 `coroutineScope { async {} }`）。
- 金额一律用 `Long`（分）传输，展示层格式化，禁止中间用 `Double`。
- 对话请求**不能自动重发**：保留 `pendingRequest` 文本，由用户点「核对原请求」触发（安全语义）。
- 请求超时：110s；轮询 `CONTEXT_PROCESSING` 最多 25 次 × 2s。前台服务/WorkManager 不要在锁屏后继续重试（涉及资金语义，需保持"用户在场"）。

### 7.3 字号与缩放

- Web 存在 **10px** 文本（模式徽章、气泡署名、输入提示），在手机上不可读：**Android 下限 11sp，正文 12sp 起**。
- 支持 `fontScale` 至 **2.0**：对话面板不得复制 `min-height:580px` / `height:640px` 固定高；改用 `weight(1f)` + `imePadding()`。
- 标签与值两列布局在 1.5× 字号时允许换行/改为纵向堆叠（参数表、收支双卡）。
- 金额大号（25sp）在 2.0× 下建议降到 20sp 或允许换行，不可裁切。
- 输入框不设固定高，`minLines=1, maxLines=4`；发送按钮随输入框高度拉伸（Web 是 64px 对齐）。

### 7.4 屏幕方向与窗口变化

| 场景 | 处理 |
|------|------|
| 竖屏手机 | 底部导航 5 项，单列，内容 16dp 边距 |
| 横屏手机（高 <480dp） | 隐藏 PageHeader 副标题（节省高度），对话整页可用；滚动位置保持 |
| 折叠屏展开 / 平板 ≥600dp | `NavigationRail`，内容最大宽 720dp 居中，避免超宽单列 |
| 平板 ≥840dp | 双栏：业务 1fr + 对话 360dp（对齐 Web 的 330–380px） |
| 旋转 | `rememberSaveable` 保存：当前 tab、输入草稿、折叠状态、滚动位置；**不要**保存验证码与一次性凭据 |
| 键盘弹出 | `imePadding`，聊天输入区上移；待确认整页滚动，确认按钮不被键盘遮挡 |

### 7.5 读屏与语义

- **实时区域**：对话状态行、上下文候选区、工作流列表、通知条 → `liveRegion = Polite`；行内错误 → `Assertive` 并 `requestFocus()`（对应 Web 的 `role=alert` + `tabIndex=-1` + `focus()`）。
- **必读标签**：模式徽章需读"当前模式：{徽章文案}"；状态徽章读完整中文（如"待确认 · 尚未执行"），不要只读"待确认"。
- **按钮语义**：`查看账户` 需带 `stateDescription = 已展开/已折叠`；`确认并执行` 禁用时应读"不可用，需先勾选确认"（`disabled()` 已有，但补充说明更好）。
- **分组**：账户网格、参数表、风险卡用 `semantics { heading() }` 与 `mergeDescendants` 控制朗读粒度；金额与币种合并为一个节点（"金额 1,234.56 元"）。
- **焦点顺序**：操作卡按 §3.6 的 1→11 顺序；终态卡在历史区，避免与待确认卡混读。
- **不可只靠颜色**：状态、风险等级、进度条都必须有文字（现有文案已满足，Android 不要删）。
- **提示音/触觉**：`确认并执行`、`取消操作`、验证通过可加 `HapticFeedbackType.LongPress`/`TextHandleMove`；不要为普通滚动加振动。

### 7.6 其他适配

- **深色模式**：Web 无；v1 建议锁定浅色（`forceDarkAllowed=false`），或提供按本文色板推导的深色方案后再放开。
- **横竖屏 + 大字号同时出现**：`PageHeader` 允许标题两行；`待确认 (N)` 徽章文字可缩写为数字气泡。
- **语言**：全部中文（`zh-CN`）；金额、日期用 `Locale.CHINA`；不需要 RTL，但避免在代码里硬编码左右边距（用 `start/end`）。
- **动态字体**：CJK 字体在 Android 上为 Noto Sans CJK，笔画较 Web 的 Microsoft YaHei 略粗，标题 700 可降为 600 以接近观感。
- **长文本**：动作编号、回执编号、code 必须 `softWrap`（Web 用 `overflow-wrap:anywhere`），禁止 `maxLines=1` 截断。

## 8. 与 Web 的差异、坑位与实现决策

| # | 现象 | 影响 | 建议 |
|---|------|------|------|
| 1 | `--green` 实际等于主色 `#3A5ECF` | 若照搬变量名会做出"绿色主色" | Android 只建蓝系令牌，不建 `green` |
